# ADR-0015: PWM driver, one timer owns its channels

Status: Accepted

## Context
The RC-car demonstration ([ADR-0013](0013-v1-scope.md)) drives two motors through an external H-bridge, one PWM line each. The driver has to fit the typestate pattern ([ADR-0007](0007-typestate-driver-api.md)) and the manual, no-HAL rule ([ADR-0003](0003-manual-drivers.md)). PWM is generated by the timer peripheral in hardware, so once configured the CPU is uninvolved and the scheduler tick rate is irrelevant to the waveform.

## Decision
A typestate `Pwm` handle in the BSP, `Uninit` until `into_active(PwmConfig)` programs the timebase, mirroring the GPIO and UART drivers. The contract lives in `specs/`.

The handle models one hardware timer: it owns the shared prescaler and auto-reload, so the PWM frequency is set once at activation and is not runtime-adjustable. It then hands out channel handles, each consuming an unconfigured GPIO pin so a pin cannot be both a PWM output and a GPIO. Channels share the frequency and have independent duty.

Duty is a normalised `u16`, full scale is 100%; the driver scales it against the live auto-reload value. Effective resolution is the timer's period count, not the full 16 bits. Each channel enables and disables its own output; the timer keeps running for the others.

The board binds this to `TIM3` for the motor channels and also exposes `TIM2` so a demo can sweep the on-board LED with no extra hardware.

## Alternatives
- Independent per-channel construction with a frequency argument each: simpler surface, but nothing stops two channels on one timer being given different frequencies, silently reconfiguring the shared timebase.
- Runtime-adjustable frequency: not needed for motor drive, and it complicates the duty scaling.
- Raw compare-value API instead of normalised duty: exposes the timer period to the caller and breaks whenever the frequency changes.
- Reuse `embedded-hal` traits: rejected for the same reason as [ADR-0003](0003-manual-drivers.md), the project defines its own contracts.

## Consequences
- `specs/` gains a PWM contract beside GPIO and UART; the BSP gains a `pwm` module.
- Full-scale duty is one period count short of a true 100% because the compare is a strict inequality; irrelevant for motor drive.
- Register values verified against the reference manual; hardware validation by an LED-sweep runbook.
